# RAMEN – not just a noodle soup?

The _Reusable Abstraction Model for Editorial Needs_ (RAMEN) helps scholarly projects structure and connect their data. Projects adapt its shared model to their sources and research questions. [Tools](/tools) can then use the same definitions to capture, annotate, and publish data.

For example, a correspondence edition can organise a letter and its transcription, annotate a name in the text, and link that occurrence to a person. The same person can then be linked to mentions in other letters.

## A Shared Conceptual Model

RAMEN distinguishes four kinds of editorial objects. In a graph, each object is represented by a **node**. **Properties** describe it, and **relationships** connect it to other nodes.

| Node type    | Purpose                                                        | Example                                                          |
| ------------ | -------------------------------------------------------------- | ---------------------------------------------------------------- |
| `Collection` | Groups content and other collections.                          | A letter brings together its surviving copies and their content. |
| `Content`    | Stores or references source material.                          | A transcription stores text; an image references a scan.         |
| `Annotation` | Adds a description, interpretation, or reference to an object. | An annotation marks a name in a text and links it to a person.   |
| `Entity`     | Represents a person, place, or other object of interest.       | The same person can be mentioned in several letters.             |

Read the arrows in <FigRef id="fig:ramen">Figure 1</FigRef> as statements: content is `PART_OF` a collection, content `HAS_ANNOTATION` an annotation, and an annotation `REFERS_TO` an entity.

**Annotations connect the modelling areas.** They can describe content, collections, entities, or other annotations. A project can mark a passage, record a source for a person's birth date, or comment on an interpretation.

Several annotations can describe the same passage, including different interpretations. Through `REFERS_TO`, an annotation can link to content, a collection, or an entity. See the [reference model](/specification/reference-model#relationships) for all permitted connections.

### Three Modelling Areas

The four node types support three overlapping areas of editorial work:

- **[Context modelling](/concepts/context)** organises material into collections, such as letters or corpora. The same content can belong to more than one collection.
- **[Content modelling](/concepts/content)** captures text, images, or other material and annotates whole objects or selected parts.
- **[Knowledge modelling](/concepts/knowledge)** describes persons, places, and other entities and records statements about them through annotations.

## Project-Specific Refinement

A **project model** defines the types of objects a project records. A correspondence edition might need `Letter`, `Witness` (a surviving copy of a letter), `Text`, `Person`, and `Place`.

**Refinement** gives a RAMEN base type a more specific project role. For example, `Letter` refines `Collection` and inherits its properties. Tools can recognise it as a collection and also use the properties and rules defined for letters.

A project can add properties and validation rules, such as requiring a letter title. It also defines which types can be connected and how many connections are allowed. For example, each witness can be required to belong to exactly one letter.

Projects can use the shared `Annotation` type directly. **Annotation shapes** define the rules for each kind of annotation. A name annotation might require a link to one `Person`; a commentary might require a comment text.

The model defines the rules; **recorded data** contains the individual letters, transcriptions, annotations, and people. The [specification](/specification) provides the exact definitions, file formats, and validation rules.

## Working with Existing Standards

Projects can retain established formats such as [TEI](https://tei-c.org/) for text encoding or reference images made available through [IIIF](https://iiif.io/). RAMEN describes how this content is organised, annotated, and connected to other objects in the edition. The [content examples](/concepts/content#using-teixml-and-ramen) show one way to map TEI-encoded names to annotations and entities.

A paragraph or table can remain encoded within a document. A separate node is useful when the project needs to link to it or describe, validate, or publish it as an object in its own right.
