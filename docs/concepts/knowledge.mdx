# Modelling Knowledge

An edition can describe the people, places, works, and events connected to its sources. RAMEN represents these as **entities**. Annotations record statements about them and connect them to content, collections, or other entities.

For example, a name annotation can connect a passage to a person. Another annotation can record a family relationship between two people, with a source or a note about uncertainty.

## Entities and Their Properties

A project can refine `Entity` into types such as `Person`, `Place`, `Work`, or `Event`. Each recorded entity has a `label` and a `uuid`, inherited from RAMEN. The project can add properties such as dates, descriptions, or external identifiers.

One person can be linked to many occurrences of a name. The written name stays in the source text; the entity represents the person identified by the project. See the [content annotation example](/concepts/content#linking-content-annotations).

## Statements and References

`HAS_ANNOTATION` attaches a statement to the object being described. `REFERS_TO` connects the annotation to the object it refers to. That reference can point to an entity, content, or a collection.

For a relationship between people, a project might refine `Annotation` into `Kinship` and declare a `spouseOf` shape. The annotation is attached to one person and refers to the other.

The statement can carry properties such as a source, date, or certainty level if the project defines them. Refining `Annotation` is optional: a project can also declare a `spouseOf` shape on the shared type.

### Symmetric Relationships

The graph records a source person and a referenced person even when the intended relationship, such as `spouseOf`, is symmetric. The project and tools must define that meaning. To find a person's spouses, a tool needs to consider both attachments to that person and annotations that refer to them. Core does not create an inverse statement automatically.

### Commenting on Statements

Annotations can themselves have annotations through `HAS_ANNOTATION`. A project can use this to comment on an identification, cite evidence, or record a different interpretation while keeping the earlier statement.

In this example, a project declares a `comment` shape with a `text` property. A comment asks which source supports the `spouseOf` statement. It is attached to the statement itself, so the original claim and the question remain separate.

The reference model allows annotations as targets of `HAS_ANNOTATION`; `REFERS_TO` targets content, collections, and entities. See the [reference model](/specification/reference-model#relationships) for the available connections.

## Connecting Authority Data

A project can store an identifier or URI from an authority service such as the [GND](https://gnd.network/) or [Wikidata](https://www.wikidata.org/) as an entity property. An annotation can record the proposed match and its evidence when that identification needs to remain a separate statement.

An external identifier provides a reference; retrieving or synchronising external records depends on the tools. For workflows connecting separate databases, see [NAKAR](https://go.thm.de/nakar).

The project model defines which statements and properties can be recorded. See the [specification](/specification) for annotation shapes and validation, or [Nori](/tools/nori) to define these rules visually.
